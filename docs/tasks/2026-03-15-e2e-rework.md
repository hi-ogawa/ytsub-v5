## Issues

### 1. `/dev` routes don't need auth — but tests login anyway

Per AGENTS.md, `/dev` routes exist to mirror extension UI **without auth**:

- `/dev` → `BookmarksPage` without auth
- `/dev/videos/:id` → `CaptionPanel` with fixture data

dev-viewer.spec.ts tests navigate to `/dev/videos/7GU_VQfgMT0` but call `login(page)` in every `beforeEach`. The 26 caption panel tests don't need auth — only the 3 sync tests (which talk to the server) do. This is ~10s of unnecessary login overhead.

This also clarifies the natural split for parallelization: tests that use `/dev` routes with fixture data need no DB at all and can run freely in parallel, while tests that need server state (sync, auth, API) share the DB and must coordinate.

### 2. Duplicated helpers (~100 lines repeated 3x)

`openPanelWithTracks()` and `createBookmarkAt()` are copy-pasted identically in:

- `dev-viewer.spec.ts` (lines 5-37)
- `video-list.spec.ts` (lines 57-88)
- `ai-prompt.spec.ts` (lines 4-35)

### 3. Too many small tests that could be merged

Several tests are thin wrappers testing one tiny assertion that could be combined into a richer flow test without losing signal. Examples:

- **dev-viewer.spec.ts**: "tab bar shows captions and bookmarks tabs" (1 assertion), "bookmarks tab shows empty state" (1 assertion), "bookmark count shown in tab label" (1 assertion) — these three test the same tab bar and could be one test walking through states
- **dev-viewer.spec.ts**: "cancel text selection hides FAB" (2 assertions) — could fold into "manual bookmark: create, highlight, and export"
- **dev-viewer.spec.ts**: "captions tab preserves scroll after switching tabs" — just checks `[data-index='0']` is visible after tab switch, barely tests anything
- **basic.spec.ts** + **auth.spec.ts** overlap: both test login/register/duplicate-username/wrong-password, one via UI and one via API. The UI tests in basic.spec.ts duplicate what the login helper already exercises every test run

### 4. `workers: 1` — no parallelization

Each file's `beforeAll` calls `setupDb()` which clears + reseeds the DB, so files can't run in parallel because they share one DB state.

But issue #1 reveals a natural split: **`/dev` route tests don't touch the DB at all**. They use fixture data loaded client-side. These can run in parallel without any DB isolation work.

| Group                 | Files                                                                  | Tests | Duration | Needs DB |
| --------------------- | ---------------------------------------------------------------------- | ----- | -------- | -------- |
| Fixture-only (`/dev`) | dev-viewer (panel), ai-prompt                                          | 31    | ~22s     | No       |
| Server/auth           | api, auth, basic, video-list, dev-viewer (sync), delete, import, toast | 46    | ~31s     | Yes      |
| Misc UI               | theme                                                                  | 1     | ~1s      | No       |

### 5. `rpc()` helper duplicated between auth.spec.ts and api.spec.ts

Different implementations with the same signature.

## Proposed Changes

### Phase 1: Split by auth boundary (biggest architectural win)

The `/dev` routes mirror extension UI with fixture data and **don't need auth or DB**. This is the natural seam for parallelization and simplification.

1. **Drop `login()` from dev-viewer caption panel tests**
   - 26 tests navigate to `/dev/videos/...` — no auth needed
   - Only the 3 sync tests (which call server APIs) keep `login()`
   - Saves ~10s (26 × 0.4s login overhead)

2. **Split dev-viewer.spec.ts along auth boundary**
   - `dev-viewer.spec.ts` — 26 caption panel tests, no login, no DB, no `setupDb()`
   - `sync.spec.ts` — sync tests from dev-viewer + video-list sync tests (all need auth + DB)
   - Enables parallel: dev-viewer can run alongside DB-dependent tests

3. **Enable parallel workers for fixture-only tests**
   - dev-viewer, ai-prompt, theme don't touch DB → run in parallel with everything else
   - Add a Playwright project group or use `fullyParallel` for these files
   - No DB isolation work needed — they never call `setupDb()`

### Phase 2: Consolidate and merge

4. **Extract shared helpers to `e2e/helper.ts`** (user took over)

5. **Merge thin tests in dev-viewer.spec.ts**
   Combine related micro-tests into richer flow tests:
   - Merge tab bar / empty state / bookmark count → "bookmarks tab lifecycle"
   - Merge cancel selection + scroll preservation into existing tests
   - Target: ~26 → ~18 tests

6. **Consolidate auth tests**
   - basic.spec.ts has 6 auth UI tests + auth.spec.ts has 11 API auth tests = 17 auth tests
   - Merge basic.spec.ts auth tests into auth.spec.ts (one "auth" file)
   - Keep only the nav/routing tests from basic.spec.ts that aren't auth-specific

7. **Merge small single-purpose files**
   - `theme.spec.ts` (1 test) + `toast.spec.ts` (2 tests) → fold into existing files
   - `delete.spec.ts` (2 tests) → merge into video-list / dev-viewer

### Phase 3: Further speed improvements

8. **Persistent auth via `storageState`** for tests that do need login
   - Login once in `global-setup.ts`, save to `e2e/.auth/user.json`
   - Remaining auth-dependent tests (~20) skip the login UI flow
   - Saves ~8s (20 × 0.4s)

9. **Extract API test helper**
   - Unify `rpc()` and `getAuthCookie()` into `e2e/api-helper.ts`
